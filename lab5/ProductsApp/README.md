# Лабораторна робота №5 — Навігація в React Native з Expo Router

## Інструкція запуску

### Вимоги
- Node.js 
- npm або yarn
- Застосунок **Expo Go** на телефоні (iOS або Android) або емулятор

### Кроки

```bash
# 1. Клонувати репозиторій
git clone https://github.com/MobileLabsRN2026/lab5.git
cd lab5

# 2. Встановити залежності
npm install

# 3. Запустити проєкт
npx expo start
```

Після запуску відскануйте QR-код у Expo Go або натисніть `a` для Android-емулятора / `i` для iOS-симулятора.

## Опис реалізованого функціоналу

### Структура файлів
```
app/
├── _layout.jsx              # Кореневий макет (AuthProvider)
├── index.jsx                # Редирект на /login
├── +not-found.jsx           # Екран 404
├── (auth)/
│   ├── _layout.jsx          # Макет публічних екранів
│   ├── login.jsx            # Екран входу
│   └── register.jsx         # Екран реєстрації
└── (app)/
    ├── _layout.jsx          # Захищений макет (перевірка авторизації)
    ├── index.jsx            # Каталог товарів
    └── details/
        └── [id].jsx         # Деталі товару (динамічний маршрут)
context/
└── AuthContext.jsx          # Глобальний контекст авторизації
data/
└── products.js              # Масив тестових товарів
```

### Функціонал
- **Авторизація** — вхід і реєстрація через глобальний `AuthContext`
- **Захищені маршрути** — неавторизовані користувачі автоматично перенаправляються на `/login`
- **Каталог товарів** — список із `FlatList`, зображення, назва, ціна
- **Деталі товару** — динамічний маршрут `details/[id]`, повна інформація
- **Вихід** — кнопка у хедері викликає `logout()` і повертає на логін
- **Екран 404** — обробка неіснуючих маршрутів

## Висновки — відповіді на контрольні запитання

**1. Як Expo Router реалізує перенаправлення неавторизованого користувача?**

У файлі `app/(app)/_layout.jsx` виконується перевірка значення `isAuthenticated` з контексту. Якщо воно `false`, компонент повертає `<Redirect href="/login" />`, що автоматично перенаправляє користувача без рендерингу захищеного контенту.

**2. Різниця між `<Link>` та `router.push()`?**

`<Link>` — це декларативний компонент для навігації у JSX-розмітці (аналог `<a>` у вебі). `router.push()` — це програмна навігація, яку викликають із обробників подій або бізнес-логіки (наприклад, після успішного логіну). `<Link asChild>` дозволяє передати навігаційну поведінку дочірньому компоненту.

**3. Як працюють динамічні маршрути і як отримати параметри?**

Файл із назвою у квадратних дужках, наприклад `[id].jsx`, створює динамічний маршрут. Expo Router автоматично передає значення сегмента URL як параметр. Для отримання використовується хук `useLocalSearchParams()`: `const { id } = useLocalSearchParams()`.

**4. Чому стан авторизації зберігати в React Context, а не локальному стані?**

Локальний стан доступний лише всередині одного компонента. Стан авторизації потрібен у багатьох непов'язаних компонентах: лейаутах, екранах, хедерах. React Context забезпечує єдине джерело правди, доступне будь-якому компоненту в дереві без передачі пропсів через кожен рівень (prop drilling).

**5. Для чого групи маршрутів і як вони впливають на URL?**

Групи маршрутів `(folderName)` дозволяють логічно організувати файли проєкту (наприклад, публічні та приватні екрани) і застосовувати спільні лейаути. Назва папки в дужках **ігнорується** в URL — маршрут `(auth)/login.jsx` відповідає URL `/login`, а не `/auth/login`.
